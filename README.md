# Kneeboard Design System v2

This package defines rules and templates for turning aircraft kneeboard/checklist source material into consistent HTML kneeboard pages that can later be exported as PNGs.

It is not a program. It is a reusable authoring harness, a set of skills, visual style guides, format guides, and templates.

## Core model

Every kneeboard is generated by combining four things:

```txt
Source material + aircraft content + format + style = HTML kneeboard page(s)
```

- **Source material**: screenshots, existing kneeboards, manuals, notes, or previous HTML.
- **Aircraft content**: normalized checklist/reference data extracted from the source.
- **Format**: the semantic structure of the page, such as normal checklist, combat fence, weapons, navigation, carrier operations, or reference tables.
- **Style**: the visual language, such as WW2 day, WW2 night, cold war day, cold war night, or modern unified.

## Design principles

1. **Separate content from presentation.** Checklist content should not contain visual instructions like “yellow background.” It should contain semantic metadata like `critical`, `optional`, `condition`, `warning`, or `dcs-specific`.

2. **Separate style from format.** A weapons page and a startup page can both use WW2 Day styling. A normal checklist can be rendered in WW2 Day, Cold War Night, or Modern Unified without changing the source content.

3. **Prefer kneeboard readability over manual completeness.** A kneeboard is for fast cockpit use. Long manual procedures should be compressed into cockpit-safe action rows, notes, and references.

4. **Use DCS reality when needed.** If a procedure is simplified for DCS, mark it as DCS-specific rather than pretending it is real-world aircraft doctrine.

5. **Preserve aircraft personality without breaking the system.** The FW 190, Spitfire, MiG-21, F-14, F-16, and AH-64D should not feel identical, but they should share predictable page grammar.
